# 安全

Pi 是一个本地编码 agent。它以启动它的用户账户的权限运行,并将该用户可写的文件视为处于同一本地信任边界内。

## 项目信任

项目信任(project trust)控制 pi 是否加载项目本地的设置、资源、包和扩展。它不是沙箱,也不会限制模型在你在某目录中开始工作之后能让工具做什么。

当 pi 从当前工作目录发现以下任意一项时,即认为该项目存在需要信任的资源:

- `.pi/settings.json`
- `.pi/extensions`、`.pi/skills`、`.pi/prompts` 或 `.pi/themes`
- `.pi/SYSTEM.md` 或 `.pi/APPEND_SYSTEM.md`
- 当前目录或祖先目录中的项目级 `.agents/skills`

仅存在一个空的 `.pi` 目录不算需要信任的项目资源。

当交互式会话在一个存在需信任资源的项目中启动,且当前目录或父目录没有已保存的信任决定时,pi 遵循全局设置中的 `defaultProjectTrust`。默认值是 `"ask"`,即在 UI 可用时询问是否信任该项目。已保存的决定按规范化目录存储在 `~/.pi/agent/trust.json`,当前或父路径上距离最近的已保存决定优先于全局默认值生效。

信任一个项目后,pi 会加载该项目所有需要信任的资源,包括:

- `.pi/settings.json`
- `.pi` 下的资源,如扩展、技能、提示模板、主题和系统提示文件
- 项目设置中配置的缺失项目包
- 项目本地扩展以及由项目包管理的扩展

拒绝信任则会跳过这些受保护资源。`AGENTS.override.md`、`AGENTS.md`、`CLAUDE.md` 等上下文文件无论项目信任与否都会加载,除非禁用了上下文加载。在信任问题解决之前,pi 只加载上下文文件、用户/全局扩展和 CLI `-e` 扩展。用户/全局扩展和 CLI 扩展可以处理 `project_trust` 事件;第一个返回 是/否 决定的扩展拥有该决定权。

非交互模式(`-p`、`--mode json` 和 `--mode rpc`)不显示信任提示。在没有适用的已保存信任决定时,`defaultProjectTrust: "ask"` 和 `"never"` 会忽略这些资源,而 `"always"` 则信任它们。可以使用 `--approve`/`-a` 或 `--no-approve`/`-na` 为单次运行覆盖项目信任。

## 无内置沙箱

Pi 不包含内置沙箱。内置工具可以以 pi 进程的权限读取文件、写入文件、编辑文件和运行 shell 命令。扩展是 TypeScript 模块,以相同权限运行。包安装、shell 命令、语言服务器、测试命令和其他开发工具的行为与普通本地进程无异。

这是有意为之。pi 的设计目标就是操作本地源码树、调用项目工具链,并与用户现有的开发环境集成。一个半成品的进程内沙箱很容易被误解为安全边界,而它实际上仍然依赖宿主 shell、文件系统、包管理器、凭据和扩展代码。真正的隔离必须来自操作系统或虚拟化/容器边界。

项目信任只是一个输入加载守卫。它防止仓库在你批准之前悄悄修改 pi 的设置或扩展。它不会让不可信代码、不可信提示或不可信模型输出变得安全。来自仓库文件、注释、文档、上下文文件或构建输出的提示注入,属于预期的本地 agent 风险,pi 无法可靠地阻止。

## 运行不可信或无人监督的工作

面对不可信仓库、你无意密切监督的生成代码,或无人值守的自动化,请在受控环境中运行 pi。使用容器、VM、微型 VM、远程沙箱或带策略控制的沙箱,并且只挂载任务所需的文件和凭据。

常见模式记录在 [容器化](containerization.md) 中:

- 把整个 `pi` 进程放进容器/沙箱内运行
- 宿主机运行 pi,同时把内置工具执行路由到 Gondolin 微型 VM
- 只挂载 agent 应该访问的工作区路径
- 避免挂载宿主的 `~/.pi/agent`,除非容器确需访问宿主的会话、设置和凭据
- 只传入所需的最少 API key,或使用短生命周期凭据
- 任务不需要网络时限制网络访问
- 在把结果复制回可信系统之前审阅 diff 和输出

如果你以读写方式 bind-mount 宿主工作区,容器或 VM 内部的写入仍然可以修改宿主文件。当需要更强的防误写保护时,请使用只读挂载,或在沙箱内外复制文件。

## 报告安全问题

报告安全问题请遵循仓库的[安全策略](https://github.com/earendil-works/pi/blob/main/SECURITY.md)。安全敏感的报告不要开公开 issue。

预期的本地 agent 行为、缺少内置沙箱、来自不可信内容的提示注入,以及用户安装扩展或技能的行为,通常都在安全边界之外,除非报告展示了真实的特权边界绕过,或展示了 pi 如何授予本地用户原本不具备的访问权限。
